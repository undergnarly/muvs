# 05-01 — Production readiness for November

## Objective

Measure real first-visit behaviour of muvs.dev, remove verified production blockers, and deploy a tested release without changing the artist's visual identity or persistent content.

## Context and constraints

- Working checkout: `C:/Projects/Muvs`; never write project files in OneDrive.
- Baseline: `34564ae`; server release is managed by the existing Git/PM2 deployment.
- Preserve priority opaque Y2K/spray loading, all menu videos, 3D navigation, user effect presets and published CMS/audio.
- Dubplates stays unlisted/noindex, password-free; do not create production test downloads/listens or expose private analytics.
- No framework rewrite, paid service, off-host storage or unrelated server-app changes.
- Lab mobile emulation is not a physical handset or field Core Web Vitals. Measure menu readiness separately from loader LCP.

## Tasks

1. **First-visit performance:** capture cold/mobile and Lighthouse baselines; parallelize startup, isolate optional legacy code, stop invisible work, retain failure/static recovery and preferred-motion/data behaviour. Verify build, scoped tests and native mobile/desktop journeys.
2. **Discoverability and operations:** serve current CMS-derived public HTML/head/robots/sitemap with correct statuses; preserve private noindex routes; add compatible response security/cache policy, dependency patches, scoped health/rollback and complete local backups. Verify escaping, auth/privacy, headers, routes and production data invariance.
3. **Production interaction and handoff:** fix hidden keyboard controls/menu focus, waveform seeking/login semantics and misleading legacy contact flow; remove rejected public geo/stat writes. Run regression tests, deploy, compare measurements and record remaining content/owner launch actions.

## Success criteria

- New visitors see the original loader immediately, then a complete usable scene with no white/blank media regressions.
- Initial JavaScript and navigation work are reduced with measured evidence, not score-only claims.
- Public routes have real titles, descriptions, canonical URLs, social metadata, meaningful fallback content and crawlable links; unknown pages are real 404s.
- Private/unlisted/admin routes and analytics remain private/noindex; authenticated JSON is never publicly cached.
- Deployment is validated and recoverable; local backups include uploaded media and Dubplates, with restore instructions.
- Unit/integration/build/browser checks and exact live release verification pass; current CMS/catalog/audio/presets are unchanged except explicit filesystem permission hardening.
- Summary distinguishes completed fixes, lab limits, existing tooling debt and owner-dependent launch tasks.
